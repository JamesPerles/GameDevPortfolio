Project 01
Cyber Steel

You are a retired knight but a grave threat has appeared forcing you to take up your weapons again. You see a crack in the sky and creatures with mysterious weapons coming from a great tower. The pathway to the tower is not easy as the land around it has been destroyed requiring careful maneuvering as one fall can be certain death. Once inside the tower it is teeming with creatures, a mix of magical and technological, and at the top stands a demonic creature commanded by a hooded figure who is responsible for all this destruction. Climb the tower to face him or fail and see your world destroyed.

2D PlatformerActionBoss FightTower Climb
Developer Notes
Cyber Steel was the first game I worked on that was not a solo project. The team of 7 was originally part of a much larger group that was split up by our professors due to a lack of progress. The final team consisted of 1 project manager, 1 programmer (myself), 2 artists, 2 writers, and 1 sound designer. This project was made for our senior thesis, which had us emulate the development of a real game studio over 8 months, with each member assigned a fixed role for the entire project. Our actual development time was closer to 6 months, and at times roles shifted — I took on assistant project manager duties, and one of our writers designed the entire first level in the final month. As the sole programmer, my responsibilities went well beyond writing systems: I designed many of the gameplay mechanics and enemies, programmed two boss fights, built the main combat level, and was the keeper of the primary build for most of development. I was also responsible for integrating all artist-delivered assets into Unity, including setting up animators and hooking everything together. It was a challenging but rewarding project and the game I am most proud of.
Duration: 6 months
Team Size: 7 people
Context: Senior Thesis
Technical Details
Unity C# Scene Management
  • Used Unity's Scene Management system to emulate a cutscene in the style of a storybook — loading a dedicated scene that displays sequential illustrated panels with text, then transitioning back into gameplay once the sequence ends.
  • Used Unity's Audio Mixer to manage and route all in-game audio, controlling volume levels and mixing sound effects and music together cleanly.
  • Applied Unity's Physics Material 2D to surfaces — zero-friction materials on walls so the player slides off cleanly, and angled surfaces with zero friction so the player slides down them and cannot jump, creating deliberate no-jump zones throughout the level.

Boss.cs C# — Boss AI 
void TeleportToNextPoint()
{
    isTeleporting = true;
    StartCoroutine(TeleportAfterAnimation());
}

IEnumerator TeleportAfterAnimation()
{
    yield return new WaitForSeconds(
        teleportAnimator.GetCurrentAnimatorStateInfo(0).length
    );

    transform.position = shuffledTeleportPoints[currentIndex].position;
    currentIndex = (currentIndex + 1) % shuffledTeleportPoints.Count;
    teleportCount++;

    if (teleportCount >= 3)
    {
        teleportCount = 0;
        ShuffleTeleportPoints();
        Invoke("SpawnFireballs", fireballDelay);
    }

    isTeleporting = false;
}

void SpawnFireballs()
{
    if (fireballSound != null)
        AudioSource.PlayClipAtPoint(fireballSound, transform.position);

    foreach (Transform firePoint in firePoints)
    {
        GameObject fireball = Object.Instantiate(
            fireballPrefab, firePoint.position, Quaternion.identity
        );
        if (isLowHealth)
            fireball.GetComponent<Rigidbody2D>().linearVelocity *= 2f;
    }
}

void ShuffleList<T>(List<T> list)
{
    for (int i = 0; i < list.Count; i++)
    {
        int randomIndex = Random.Range(i, list.Count);
        T temp = list[i];
        list[i] = list[randomIndex];
        list[randomIndex] = temp;
    }
}
Code Explanation
This was the first time I had ever programmed a boss fight and so the first thing I thought to make it easy on myself would be making it a teleporting boss that uses projectiles to attack. The main problem I had to solve with the boss though was making him feel unpredictable as at the start the boss simply teleported in the exact order listed in the array and I had even run into glitches where the boss would simply stop teleporting at points. If he just teleported to the same spots in the same order every time, it would be to easy and the fight would end very quickly as a result. So I used a randomization system — the teleport points get randomised at the start and then randomized again every three teleports as their are only a max of three teleport points, meaning the boss never becomes predictable and the player will at times have to predict where the boss will go next in order to deal damage. The coroutine side of it was important too because I needed the teleport to wait for the animation to actually finish before moving him as, otherwise he'd snap to his new position mid-animation which was actually the case earlier in development. The low health speed boost on the boss was something I added later in development just to effecitvely give the boss a second phase without having to build to that much extra work — when his health drops, the boss suddenly becomes a lot more threatening as it is almost impossible to hit without a good prediction due to the speed increase. Despite doing this to make it easier I actually ended up having some extra time late in development that reused this bosses moveset entirely for its first phase and then gets a completely new moveset using a completely new script. If I did the game over again I would most likely either merge the bosses into one or put more effort into giving this boss a proper second phase rather than just making it faster.

Project 02
Ashen Crown

Monsters have destroyed your kingdom and taken you the princess captive. You thought it was all over until a knight comes to your rescue but he is barely clinging on to life. With his last breaths he frees you and gives you a tome that can give you the power to save your kingdom. Now with this tome you battle to escape the dungeon you were imprisoned in using the tome to transform yourself to battle the monsters within.

2D PlatformerTransforming MovesetDialogue SystemFantasy
Developer Notes
With Ashen Crown I was partly inspired by Cyber Steel — it was the last game I had worked on, and since it was also a platformer I wanted to see if I could build something similar entirely on my own. The main challenge I set for myself was making all the art assets from scratch. I wouldn't consider myself a strong artist, but I did take several art electives in college and even worked as an artist on a team project where we were forced to swap roles. While the art is far from polished pixel art, I'm proud of what I managed within a one-month development window, and it's a game I'd like to revisit someday when my art skills improve. For the mechanics and story, I drew inspiration from Kirby's transformation system and the classic damsel-in-distress trope — I combined them so that the hero who rescues the princess dies right after freeing her, and she must use an ancient tome to fight her way out. Since the genre overlapped with Cyber Steel I focused on adding systems I had never built before: a cutscene using Unity's Timeline, which I found surprisingly straightforward, and a dialogue system that locks player movement until all lines are exhausted.
Duration: 1 month
Team Size: Solo
Context: Personal Project
Technical Details
Unity C# Animator Timeline Animation Events
  • Used Unity's Animator to manage the player's transformation system, switching between distinct animation sets for each form the player can take.
  • Implemented Animation Events to precisely synchronise gameplay moments — such as hitbox activation and ability triggers — directly to specific frames in animations.
  • Used Unity's Timeline to author and sequence cutscenes, coordinating character animations, camera movement, and dialogue together in a single visual editor.

DialogueSystem.cs C# — Dialogue System 
private IEnumerator TypeLineRoutine(DialogueLine line)
{
    isTyping = true;
    ClearCurrentLine();
    SetActiveCharacter(line.characterIndex);

    currentLine = Object.Instantiate(linePrefab, dialogueBox, false);
    currentLine.gameObject.SetActive(true);
    currentLine.text = "";
    currentLine.rectTransform.anchoredPosition = Vector2.zero;

    if (line.characterIndex >= 0 && line.characterIndex < characters.Length)
        currentLine.color = characters[line.characterIndex].textColor;

    int charsPerFrame = 2;
    for (int i = 0; i < line.text.Length; i += charsPerFrame)
    {
        int end = Mathf.Min(i + charsPerFrame, line.text.Length);
        currentLine.text += line.text.Substring(i, end - i);
        yield return new WaitForSeconds(charDelay);
    }

    isTyping = false;
    typingCoroutine = null;
    StopCharacterAnimation(line.characterIndex);
}

private void SetActiveCharacter(int characterIndex)
{
    for (int i = 0; i < characters.Length; i++)
    {
        if (characters[i].characterSprite != null)
            characters[i].characterSprite.SetActive(false);
        if (characters[i].characterAnimator != null)
            characters[i].characterAnimator.SetBool("isDialogue", false);
    }

    if (characterIndex >= 0 && characterIndex < characters.Length)
    {
        characters[characterIndex].characterSprite?.SetActive(true);
        characters[characterIndex].characterAnimator?.SetBool("isDialogue", true);
    }
}
Code Explanation
The dialogue system needed to do two things — type out text character by character like a classic RPG, and show the right character portrait while they were talking. The coroutine handles the typing effect, revealing a couple of characters per frame with a small delay between each so it feels natural rather than just popping the full line in all at once. I hook the character index into it so it knows who's speaking, which then swaps the visible portrait and triggers their talking animation. The reason I instantiate a new text object for each line rather than just clearing and rewriting one is that it made it easier to control the layout and position of each line in the dialogue box — especially if I wanted to extend it later to show conversation history. If I were to rebuild the dialogue system I would probably look for ways to speed up or skip text entirely as in the current version you have to go through multiple lines of text each time you replay the game or die which can be rather annoying especially when testing the game.

Project 03
Rogue Space

In Rogue Space the player flies through space fighting infinite waves of alien creatures. After each wave the aliens drop an orb that can power up your ship — select from an assortment of new abilities including more firing points, new weapons, strengthening your stats, or even cloning your ship. Last as long as you can against the aliens as they only get stronger and stronger the longer you last until they finally overwhelm you.

RogueliteSpace ShooterUpgrade SystemEndless
Developer Notes
With Rogue Space I was inspired by two things: classic arcade top-down space shooters like Galaga, and roguelite games. I started with the straightforward part — programming the player and enemies — then tackled the roguelite systems afterward. I came up with three categories of powerup: stat boosts (damage, speed, defense, HP), weapon swaps (bombs, discs, laser swords and more), and unique abilities like cloning your ship. The clone ship ended up being the trickiest thing to program, since I had trouble making the clone die instead of the player when HP hit zero, but I got it working eventually. I also made the game infinite — waves never end — and balanced this by scaling enemy stats progressively with each wave so the difficulty always catches up to the player eventually. Like Ashen Crown, I made all the art myself, though the NES-inspired sprite style made that much faster this time around. The overall focus was build customization: letting players experiment with different combinations while keeping the game challenging enough that surviving indefinitely is never guaranteed.
Duration: 1 month
Team Size: Solo
Context: Personal Project
Technical Details
Unity C# Infinite Waves Wave Timeout Camera
  • Waves are infinite and randomly generated using per-enemy spawn chances, with stat multipliers scaling each wave higher — and a timeout system that automatically clears any remaining enemies if the timer expires, preventing the player from getting soft-locked by unkillable or stuck enemies.
  • Created an infinitely looping background that scrolls and seamlessly wraps to simulate the ship moving through space without ever reaching an edge.
  • Adjusted the Camera's orthographic size and viewport to lock the aspect ratio and frame the game like a classic 2D arcade top-down shooter.

WaveManager.cs C# — Wave System 
private IEnumerator SpawnWaveCoroutine()
{
    WaveData baseWave = waves[Mathf.Min(currentWaveIndex, waves.Length - 1)];

    enemiesAlive = 0;
    enemiesSpawned = 0;
    totalEnemiesKilled = 0;
    totalEnemies = Mathf.Min(
        baseWave.enemyCount + currentWaveIndex * 2,
        maxEnemiesPerWave
    );

    AdjustSpawnChance(baseWave);
    NormalizeSpawnChance(baseWave);

    while (enemiesSpawned < totalEnemies)
    {
        if (enemiesAlive < maxEnemiesAlive)
        {
            SpawnRandomEnemy(baseWave);
            enemiesSpawned++;
        }
        yield return new WaitForSeconds(baseWave.spawnInterval);
    }

    StartCoroutine(WaveSafetyCheck());
    activeWaveCoroutine = null;
}

void SpawnRandomEnemy(WaveData wave)
{
    int index = Random.Range(0, wave.enemies.Count);
    WaveData.EnemySpawn enemy = wave.enemies[index];

    int attempts = 0;
    while (Random.value > enemy.spawnChance && attempts < 10)
    {
        index = Random.Range(0, wave.enemies.Count);
        enemy = wave.enemies[index];
        attempts++;
    }

    GameObject spawnedEnemy = Object.Instantiate(
        enemy.enemyPrefab, spawnPoint.position, Quaternion.identity
    );
    enemiesAlive++;

    float hpMult  = 1f + currentWaveIndex * 0.1f;
    float spdMult = 1f + currentWaveIndex * 0.05f;
    float dmgMult = 1f + currentWaveIndex * 0.1f;

    EnemyController ec = spawnedEnemy.GetComponent<EnemyController>();
    if (ec != null) ec.HP *= hpMult;

    Melee m = spawnedEnemy.GetComponent<Melee>();
    if (m != null) m.moveSpeed *= spdMult;

    EnemyProjectile prj = spawnedEnemy.GetComponent<EnemyProjectile>();
    if (prj != null) prj.damage *= dmgMult;
}
Code Explanation
The wave system runs infinitely — each wave spawns enemies randomly based on individual spawn chances, with stat multipliers on health, speed, and damage increasing every wave so difficulty keeps climbing. The main focus of the system though was the WaveSafetyCheck timeout: it tracks how long a wave has been active and if enemies are still alive after the timer expires it clears them automatically, preventing the player from being stuck waiting on a bugged or unreachable enemy and losing through no fault of their own. If I were doing this again I'd separate the difficulty scaling into its own system rather than having the multiplier math sit inside the spawner.

Project 04
Echoes Of Darkness

You find yourself inside an abandoned power plant shrouded in total darkness. Your only source of light is your sonar — press E to send out a pulse that briefly illuminates the world around you in green light. Navigate the pitch black facility, avoid falling into the water below, and locate 3 relay stations scattered across the plant. Hit each one with your sonar to bring them back online. Once all 3 are activated, find the generator and ping it with your sonar to restore power — and escape the darkness.

First PersonAtmosphericPuzzleExplorationHorror
Developer Notes
My main goal with Echoes of Darkness was to have an Unreal Engine project in my portfolio. I designed the mechanics with simplicity in mind so I wouldn't get blocked trying to master a new engine while also building a complex game. The concept of navigating total darkness with a sonar pulse as your only light source felt like a natural fit for the constraint. I sourced free assets from the Unreal Marketplace and got to work learning C++, programming the systems, and designing the level. The hardest part was Unreal's Niagara particle system — getting the sonar pulse to look and feel like an actual sonar wave took over a day of iteration before the shape and timing were right. I also hit a frustrating issue where many of the downloaded textures came in corrupted, forcing me to manually test each one to find which could be used. Once the core sonar was working I added the relay activation system, hiding three targets around the level that must be lit up before the player can reach the goal. Finally I layered in some light platforming to give the game more challenge beyond pure exploration.
Duration: 3 weeks
Team Size: Solo
Context: Personal Project
Technical Details
Unreal Engine 5 C++ Niagara VFX Enhanced Input
  • Built a custom sonar pulse system entirely in C++ — firing a radially expanding point light that travels forward from the player, illuminating geometry with green light before fading out, with a cooldown preventing spamming.
  • Implemented a relay activation system that checks each tick whether the sonar wave front passes within a set proximity of a relay actor — requiring the player to physically aim and fire near each object rather than just being in the same room.
  • Used UE5's Water Plugin for the kill volume — falling into water triggers a camera fade to black, disables input, and reloads the level after a short delay.
  • All game logic — relay tracking, door destruction, win condition — is handled through a lightweight GameRelayManager actor that listens for relay activation events and responds when all three are online.

PlayerCharacter.cpp C++ — Sonar Pulse System 
void APlayerCharacter::SonarPulse()
{
    if (!bCanUseSonar) return;
    bCanUseSonar = false;

    GetWorldTimerManager().SetTimer(
        SonarCooldownHandle, this,
        &APlayerCharacter::ResetSonarCooldown,
        SonarCooldown, false
    );

    SonarForwardDir = GetActorForwardVector();
    SonarOrigin = GetActorLocation()
        + SonarForwardDir * SonarSpawnOffset
        + FVector(0.f, 0.f, SonarHeightOffset);

    CurrentSonarRadius = 0.f;
    CurrentForwardTravel = 0.f;
    bSonarActive = true;

    SonarLight = GetWorld()->SpawnActor<APointLight>(
        SonarOrigin, FRotator::ZeroRotator
    );

    GetWorldTimerManager().SetTimer(
        SonarUpdateHandle, this,
        &APlayerCharacter::UpdateSonarLight,
        0.016f, true
    );
    GetWorldTimerManager().SetTimer(
        RelayCheckHandle, this,
        &APlayerCharacter::CheckSonarRelays,
        0.016f, true
    );
}
Code Explanation
The sonar was the core mechanic of the whole game so getting it to feel right was the most important thing. The way it works is it prevents the player from spamming it with a cooldown flag, then spawns a light along with a particle effect at a set distance in front of the player. If I were to program a system like this again I would change a lot as this was my first game in Unreal. The biggest thing I would fix is actually getting the sonar to move from the player's position outward, no matter what I tried I could not get it to work how I wanted it to, so the light just spawns in a set position in front of the player. I would also fix an issue where if the player is too close to a wall the light spawns behind it, leaving the player in the dark.

Project 05
Zombie Survival

A game where you survive the zombie apocalypse. Try your best to save your base from the waves of the zombie horde that approach. Fight them back with your gun and try to pick up whatever ammo you can from the rotting corpses of the zombies you gun down. If you can't save your base from the zombies it is game over.

SurvivalTower DefenseShooterZombies
Developer Notes
Zombie Survival was made for my Digital Game Design 3 class, where we had one week to build a game around a professor-assigned theme — that week's theme was horror, timed around Halloween. I wanted to make something that stood out from a typical zombie game, so I made it a tower defense where the player defends a base rather than themselves — the player character is invincible, which shifts all the pressure onto protecting the structure. The game ended up being my best work from that semester, so my professor offered it as my final project with extra polish time. I used that time to add an ammo system, a knife fallback weapon for when ammo runs out, new enemy types including tanky big zombies and fast zombie dogs, additional levels with increased difficulty, and a boss enemy that can stun the player temporarily to create moments of real pressure.
Duration: 1 month
Team Size: Solo
Context: Course Project
Technical Details
Unity C#
  • Built a weighted zombie spawner that selects which zombie type to spawn each interval using cumulative probability — each prefab is assigned a spawn chance percentage and a random roll walks the cumulative total to pick one.
  • The player is invincible — the base structure is the real health bar, forcing the player to defend it rather than just survive personally.
Code Example
ZombieSpawner.cs C# — Zombie Spawner 
private void Update()
{
    if (Time.time >= nextSpawnTime)
    {
        float totalSpawnChance = 0f;
        foreach (var option in spawnOptions)
            totalSpawnChance += option.spawnChance;

        float randomValue = Random.Range(0f, totalSpawnChance);
        float cumulativeChance = 0f;
        GameObject selectedPrefab = null;

        foreach (var option in spawnOptions)
        {
            cumulativeChance += option.spawnChance;
            if (randomValue <= cumulativeChance)
            {
                selectedPrefab = option.prefab;
                break;
            }
        }

        if (selectedPrefab != null)
        {
            GameObject zombie = Object.Instantiate(
                selectedPrefab, transform.position, transform.rotation
            );
            ZombieController zc = zombie.GetComponent<ZombieController>();
            if (zc != null)
            {
                Vector3 dir = zc.GetComponent<Rigidbody2D>().linearVelocity.normalized;
                if (dir != Vector3.zero)
                {
                    float angle = Mathf.Atan2(dir.y, dir.x) * Mathf.Rad2Deg;
                    zombie.transform.rotation = Quaternion.AngleAxis(angle, Vector3.forward);
                }
            }
        }

        nextSpawnTime = Time.time + spawnRateInSeconds;
    }
}
Code Explanation
The spawner needed to be able to handle multiple zombie types where some are rarer than others — I didn't want it to just be a coin flip between every type equally. The system works by adding up all the spawn chances into a total, rolling a random number against that total, then walking through the list cumulatively until it lands somewhere. That way I can set regular zombies at a high chance and something like a boss zombie at a very low chance, and it just works without me having to write special case logic for each type. Adding a new zombie type later was also really easy — just add it to the list with a spawn chance and the system handles the rest. The rotation code at the bottom was a late addition because zombies were spawning facing the wrong direction and it looked weird. If I was building this again I'd probably move the total spawn chance calculation out of Update since it's recalculating every frame which would be very wasteful and inefficent on a much larger game but this was also from when I was still a student and I have improved a lot as a programmer since then.
